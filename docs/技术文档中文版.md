## 一、概述

**Neko Custom Discs** 是一个 Fabric 模组，作用是把玩家本地的 `.ogg` 音乐文件变成 Minecraft 里的自定义音乐唱片。

核心能力：

- 通过 **Cloth Config** 提供游戏内配置界面；
- 扫描用户指定的本地目录，寻找音频素材；
- 动态注册自定义唱片物品（record item）；
- 在运行时写出**运行时资源包（runtime resource pack）**，让客户端能播放这些音乐。

工程规模：

- 支持 **21 个 Minecraft 版本**，从 `1.20.1` 一直到 `26.3`；
- 源码分为**两套独立的构建树**：`legacy/`（旧版）与 `modern26/`（26.x 新版）；
- 分发方式：在 `dist/` 目录中预编译好所有版本的成品 jar，再借助版本清单 `release-manifest.json` 自动同步到 Modrinth。

## 二、快速上手与用户指南

本页覆盖安装前置条件、legacy（`1.20.1`–`1.21.11`）与 modern（`26.1`–`26.3`）两套源码树各自的运行依赖、本地音乐文件夹配置、命令用法、资源包自动挂载，以及已知的技术限制。

### 1. 前置条件与运行依赖

要让 Neko Custom Discs 正常运行，目标 Minecraft 实例需要对应的模组加载器与库环境。由于代码分为 legacy 与 modern26 两套树，所需的 Java 运行时与依赖版本也不同。

| Minecraft 版本范围 | 所需 Java | Fabric Loader | Fabric API | Cloth Config API | Mod Menu（可选） |
|---|---|---|---|---|---|
| `1.20.1` – `1.21.11`（Legacy） | Java 21 | ≥ 0.14.21 | 跟随 MC 版本 | 跟随 MC 版本 | 跟随 MC 版本 |
| `26.1` – `26.3`（Modern） | **Java 25** | ≥ 0.20.1 | `0.145.1+26.1` 至 `0.165.2+26.3` | `26.1.154` 至 `26.3.159` | `18.0.2` 至 `21.0.0` |

> 关键点：modern26 树（26.x）强制要求 **Java 25**，这是 Mojang 在 26.1 之后引入的要求；legacy 树使用 Java 21 即可。

### 2. 音乐源文件夹配置与扫描

模组在游戏启动时，会扫描一个指定的本地目录，寻找 `.ogg`（Ogg Vorbis）音频文件。MP3 与 WAV 格式在底层 Minecraft 音效引擎中**不被支持**（除非事先转换好）。

**默认音乐源路径：**

- 路径：`<游戏目录>/config/customdiscs/music/`
- 转换示例（把 mp3 转成 ogg）：`ffmpeg -i input.mp3 -c:a libvorbis output.ogg`

**通过 Cloth Config 界面配置：**

玩家可以在游戏内用 **Mod Menu** 配置音乐源目录、唱片音量、合成配方开关等：

1. 依次打开 `Esc` → `Mods` → `Neko Custom Discs` → `Configure`；
2. 修改「音乐源文件夹」路径（支持相对于游戏目录的相对路径，也支持绝对路径）；
3. 新增或删除 `.ogg` 文件后，**重启游戏**以触发唱片的重新注册。

### 3. 物品获取与命令执行

每一个被扫描到的 `.ogg` 文件，都会动态生成一个对应的自定义唱片物品。获取渠道主要有三种：

1. **创造模式物品栏（Creative Tab）**：放在名为 `Custom Discs` 的自定义创造标签页下；
2. **命令**：使用 `/customdiscs give <id> [数量]`，其中 `<id>` 对应源文件名**转为小写并去掉 `.ogg` 后缀**；
3. **合成配方**：用纸张围住核心材料（默认是金锭）来合成。

### 4. 资源包自动挂载架构

为了让这些自定义音频文件能在 Minecraft 客户端里被听见，模组会动态写出一个临时资源包结构。

**资源生成数据流：**

1. **目录生成**：文件被编译进 `resourcepacks/CustomDiscs/`；
2. **素材结构**：模组写出 `assets/customdiscs/sounds.json`，并一并复制 `.ogg` 音频素材；
3. **运行时挂载**：模组以「尽力而为」的方式调用 `ResourcePackManager`（legacy）或 `PackRepository`（modern26），尝试在运行时自动激活 `CustomDiscs` 资源包。如果自动挂载失败，玩家需要手动在 `Options` → `Resource Packs` 里启用它。

### 5. 已知限制与技术约束

在部署前，用户与开发者都应注意以下明确的功能限制：

1. **1.21+ 唱片机播放缺口**：在 Minecraft 1.21 及之后，物理唱片机的播放需要 `JukeboxSong` 数据驱动注册表。由于动态资源包生成器只输出 `assets`（`sounds.json` 与 `.ogg`），而**没有输出** `data/minecraft/jukebox_song/*.json` 数据包定义，因此在 1.21+ 版本上，自定义唱片插入唱片机后**可能不发声**。
2. **环境限制（仅客户端）**：`fabric.mod.json` 中声明的 `environment` 值为 `"client"`。因此专用服务器**不会加载**本模组，纯服务器环境下 `/customdiscs give` 命令不可用（除非把该值改为 `"*"`）。
3. **资源包挂载为尽力而为**：运行时的资源包挂载是非阻塞、依赖回退机制的，偶尔仍可能需要玩家通过游戏内资源包菜单手动激活。

## 三、仓库结构与架构

本页梳理 Neko Custom Discs 仓库（`nekocustomdiscs`）的目录树与架构布局，详细说明根配置文件、分发产物、版本清单、辅助脚本，以及——最关键的——源码为何被分叉为两套独立的构建树（`legacy/` 与 `modern26/`）。

### 1. 根目录结构

仓库根目录放置了配置文件、自动化流水线、图标素材，以及支撑 21 个 Minecraft 版本的两套主源码树：

```
.
├── .github/workflows/publish-modrinth.yml   # 自动同步到 Modrinth 的 CI 流水线
├── release-manifest.json                    # 21 个版本发布的唯一事实来源（single source of truth）
├── tools/sync_modrinth.py                   # 幂等的 Modrinth 同步脚本
├── dist/                                    # 全部 21 个目标版本的预编译成品（约 588 KB）
├── legacy/                                  # MC 1.20.1–1.21.11 的源码树（Yarn 映射 + JDK 21）
├── modern26/                                # MC 26.1–26.3 的源码树（Mojang 官方命名 + JDK 25）
├── icon.png / icon-256.png                  # 项目与 Mod Menu 的品牌素材
├── LICENSE                                  # MIT 许可证
└── .gitignore                               # 构建缓存、Loom 缓存、凭据排除
```

### 2. 代码分叉的原因（legacy 与 modern26）

源码之所以被拆成两套独立的构建树（`legacy/` 与 `modern26/`），是因为 Minecraft 在 **26.1** 版本发生了根本性变化：放弃了运行时混淆（runtime obfuscation），并改变了底层 Java 运行时要求。

| 维度 | `legacy/`（MC 1.20.1–1.21.11） | `modern26/`（MC 26.1–26.3） |
|---|---|---|
| 目标 Java 版本 | Java 21 | **Java 25**（Mojang 26.1+ 强制要求） |
| Gradle 引擎 | Gradle 8.14 | Gradle 9.8.2 |
| Fabric Loom 插件 | `fabric-loom` 1.10 / 1.12 / 1.13（按 MC 版本分层） | `net.fabricmc.fabric-loom` 1.20.0-alpha.19（未映射） |
| 混淆映射 | Yarn Mappings | **无**（Mojang 直接发布未映射的官方命名） |
| 主要代码标识符 | Yarn 类名、`MusicDiscItem`、`jukeboxPlayable` | Mojang 官方命名（`Component`、`Item.Properties`、`PackRepository`） |

### 3. 分发产物与清单存储

`dist/` 目录存放着全部 21 个受支持 Minecraft 版本的预编译 `.jar` 文件，并配套 `release-manifest.json` 作为权威的元数据登记表。

- **为什么把预编译 jar 放进 `dist/`？** 在本地或 CI 中重新构建 21 条不同的 Fabric Loom 链耗时相当可观（每个版本因客户端 jar 重映射与依赖解析需要 4 到 13 分钟）。直接提交最终不足 600 KB 的二进制产物，可保证确定性、即时的可复现性，以及快速的 CI 同步。
- **`release-manifest.json`**：作为 GitHub Actions 发布流程的唯一事实来源，定义了版本 slug、目标游戏加载器、依赖映射、更新日志，以及密码学 **SHA1** 哈希值。

### 4. 自动化、工具与忽略项

其余的顶层组件负责管理 CI 同步与本地工作区清理：

- **`.github/workflows/publish-modrinth.yml`**：在推送改动 `dist/**` 或 `release-manifest.json` 时触发，调用同步脚本把发布内容镜像到 Modrinth。
- **`tools/sync_modrinth.py`**：基于 Python 的**幂等**同步脚本，会把本地的 SHA1 哈希与远端 Modrinth 状态比对，创建缺失的版本或替换不匹配的二进制文件。
- **`.gitignore`**：排除本地 Gradle 构建缓存（`.gradle/`、`build/`、`build26/`）、Python 字节码（`__pycache__/`）、较大的 Mojang 客户端 jar（`tools/26.3-client.jar`、`loom-cache/`），以及本地环境密钥（`.env`、token 等）。
