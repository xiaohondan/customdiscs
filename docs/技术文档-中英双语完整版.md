## 一、概述 / Overview

**English**
Neko Custom Discs is a Fabric mod designed to turn local `.ogg` music files into custom Minecraft music discs. It provides an in-game configuration interface via Cloth Config to scan user-specified directories for audio assets, dynamically register custom record items, and write runtime resource packs. The codebase is engineered to support **21 Minecraft versions** spanning `1.20.1` through `26.3`, organized into two distinct build trees (`legacy/` and `modern26/`). Distribution is managed via prebuilt artifacts in `dist/` synchronized automatically to Modrinth using a version manifest.

**中文**
**Neko Custom Discs** 是一个 Fabric 模组，作用是把玩家本地的 `.ogg` 音乐文件变成 Minecraft 里的自定义音乐唱片。它通过 **Cloth Config** 提供游戏内配置界面，扫描用户指定的本地目录寻找音频素材，动态注册自定义唱片物品（record item），并在运行时写出运行时资源包（runtime resource pack）。工程上支持 **21 个 Minecraft 版本**（从 `1.20.1` 到 `26.3`），源码分为两套独立的构建树：`legacy/`（旧版）与 `modern26/`（26.x 新版）。分发方式是在 `dist/` 目录中预编译好所有版本的成品 jar，再借助版本清单 `release-manifest.json` 自动同步到 Modrinth。

**Core capabilities / 核心能力**
- In-game configuration UI via **Cloth Config**.（通过 Cloth Config 提供游戏内配置界面。）
- Scans a user-designated local directory for audio assets.（扫描用户指定的本地目录，寻找音频素材。）

- Writes a runtime resource pack at runtime so the client can play the music.（在运行时写出运行时资源包，让客户端能播放这些音乐。）

### 2. 音乐源文件夹配置与扫描 / Music Source Folder Configuration & Scanning

**English**
The mod scans a designated local directory for `.ogg` (Ogg Vorbis) audio files upon game launch. MP3 and WAV formats are unsupported by the underlying Minecraft sound engine without prior conversion.

- **Default Source Path**: `<game_directory>/config/customdiscs/music/`
- **Conversion Example**: `ffmpeg -i input.mp3 -c:a libvorbis output.ogg`

Players can configure the source directory, disc volume, and recipe toggles in-game via **Mod Menu**:
1. Navigate to `Esc` → `Mods` → `Neko Custom Discs` → `Configure`;
2. Modify the music source folder path (supports relative game-directory paths or absolute paths);
3. Restart the game after adding or removing `.ogg` files to trigger disc re-registration.

**中文**
模组在游戏启动时会扫描一个指定的本地目录，寻找 `.ogg`（Ogg Vorbis）音频文件。MP3 与 WAV 格式在底层 Minecraft 音效引擎中**不被支持**（除非事先转换好）。

- **默认音乐源路径**：`<游戏目录>/config/customdiscs/music/`
- **转换示例**（把 mp3 转成 ogg）：`ffmpeg -i input.mp3 -c:a libvorbis output.ogg`

玩家可以在游戏内用 **Mod Menu** 配置音乐源目录、唱片音量、合成配方开关等：
1. 依次打开 `Esc` → `Mods` → `Neko Custom Discs` → `Configure`；
2. 修改「音乐源文件夹」路径（支持相对于游戏目录的相对路径，也支持绝对路径）；
3. 新增或删除 `.ogg` 文件后，**重启游戏**以触发唱片的重新注册。

### 3. 物品获取与命令执行 / Item Acquisition and Command Execution

**English**
Custom record items are generated dynamically for every discovered `.ogg` file. They can be retrieved through three primary channels:

1. **Creative Tab**: Placed under the custom "Custom Discs" creative inventory tab.
2. **Commands**: Executed via `/customdiscs give <id> [quantity]`, where `<id>` corresponds to the source filename converted to lowercase without the `.ogg` extension.
3. **Crafting Recipe**: Surrounding paper with primary core ingredients (default: gold ingots).

**中文**
每一个被扫描到的 `.ogg` 文件，都会动态生成一个对应的自定义唱片物品。获取渠道主要有三种：

1. **创造模式物品栏（Creative Tab）**：放在名为 `Custom Discs` 的自定义创造标签页下；
2. **命令**：使用 `/customdiscs give <id> [数量]`，其中 `<id>` 对应源文件名**转为小写并去掉 `.ogg` 后缀**；
3. **合成配方**：用纸张围住核心材料（默认是金锭）来合成。

### 4. 资源包自动挂载架构 / Resource Pack Auto-Mounting Architecture

**English**
To make custom audio files audible within the Minecraft client, the mod dynamically writes a temporary resource pack structure.

**Resource Generation Data Flow**
1. **Directory Generation**: Files are compiled into `resourcepacks/CustomDiscs/`.
2. **Asset Structure**: The mod writes `assets/customdiscs/sounds.json` alongside the copied `.ogg` assets.
3. **Runtime Mounting**: A best-effort invocation of `ResourcePackManager` (legacy) or `PackRepository` (modern 26.x) attempts to automatically activate the `CustomDiscs` resource pack at runtime. If automatic mounting fails, players must manually enable it under `Options` → `Resource Packs`.

**中文**
为了让这些自定义音频文件能在 Minecraft 客户端里被听见，模组会动态写出一个临时资源包结构。

**资源生成数据流**
1. **目录生成**：文件被编译进 `resourcepacks/CustomDiscs/`；
2. **素材结构**：模组写出 `assets/customdiscs/sounds.json`，并一并复制 `.ogg` 音频素材；
3. **运行时挂载**：模组以「尽力而为」的方式调用 `ResourcePackManager`（legacy）或 `PackRepository`（modern26），尝试在运行时自动激活 `CustomDiscs` 资源包。如果自动挂载失败，玩家需要手动在 `Options` → `Resource Packs` 里启用它。

### 5. 已知限制与技术约束 / Known Limitations & Technical Constraints

**English**
Users and developers should take note of several explicit functional limitations before deployment:

1. **1.21+ Jukebox Playlist Gap**: In Minecraft 1.21 and later, `JukeboxSong` data-driven registries are required for physical jukebox playback. Because the dynamic resource pack generator only outputs `assets` (`sounds.json` and `.ogg`) and omits `data/minecraft/jukebox_song/*.json` data pack definitions, custom records on 1.21+ versions may not produce sound when inserted into a jukebox.
2. **Environment Restriction**: The `fabric.mod.json` configuration declares an `environment` value of `"client"`. Consequently, dedicated servers will not load the mod, rendering the `/customdiscs give` command unavailable on pure servers unless reconfigured to `"*"`.
3. **Best-Effort Mounting**: Runtime resource pack mounting is non-blocking and fallback-reliant; manual activation via the in-game resource pack menu may occasionally be required.

**中文**
在部署前，用户与开发者都应注意以下明确的功能限制：

1. **1.21+ 唱片机播放缺口**：在 Minecraft 1.21 及之后，物理唱片机的播放需要 `JukeboxSong` 数据驱动注册表。由于动态资源包生成器只输出 `assets`（`sounds.json` 与 `.ogg`），而**没有输出** `data/minecraft/jukebox_song/*.json` 数据包定义，因此在 1.21+ 版本上，自定义唱片插入唱片机后**可能不发声**。
2. **环境限制（仅客户端）**：`fabric.mod.json` 中声明的 `environment` 值为 `"client"`。因此专用服务器**不会加载**本模组，纯服务器环境下 `/customdiscs give` 命令不可用（除非把该值改为 `"*"`）。
3. **资源包挂载为尽力而为**：运行时的资源包挂载是非阻塞、依赖回退机制的，偶尔仍可能需要玩家通过游戏内资源包菜单手动激活。

### 2. 代码分叉的原因（legacy 与 modern26）/ Codebase Bifurcation Rationale

**English**
The codebase is bifurcated into two independent source trees (`legacy/` and `modern26/`) because Minecraft underwent fundamental changes in version 26.1, abandoning runtime obfuscation and shifting the underlying Java runtime requirements.

| Dimension | `legacy/` (MC 1.20.1–1.21.11) | `modern26/` (MC 26.1–26.3) |
|---|---|---|
| Target Java Version | Java 21 | **Java 25** (Mandated by Mojang 26.1+) |
| Gradle Engine | Gradle 8.14 | Gradle 9.8.2 |
| Fabric Loom Plugin | `fabric-loom` 1.10 / 1.12 / 1.13 (Tiered by MC version) | `net.fabricmc.fabric-loom` 1.20.0-alpha.19 (Unmapped) |
| Obfuscation Mappings | Yarn Mappings | **None** (Mojang ships unmapped official names) |
| Primary Code Identifiers | Yarn class names, `MusicDiscItem`, `jukeboxPlayable` | Mojang official names (`Component`, `Item.Properties`, `PackRepository`) |

**中文**
源码之所以被拆成两套独立的构建树（`legacy/` 与 `modern26/`），是因为 Minecraft 在 **26.1** 版本发生了根本性变化：放弃了运行时混淆（runtime obfuscation），并改变了底层 Java 运行时要求。

| 维度 | `legacy/`（MC 1.20.1–1.21.11） | `modern26/`（MC 26.1–26.3） |
|---|---|---|
| 目标 Java 版本 | Java 21 | **Java 25**（Mojang 26.1+ 强制要求） |
| Gradle 引擎 | Gradle 8.14 | Gradle 9.8.2 |
| Fabric Loom 插件 | `fabric-loom` 1.10 / 1.12 / 1.13（按 MC 版本分层） | `net.fabricmc.fabric-loom` 1.20.0-alpha.19（未映射） |
| 混淆映射 | Yarn Mappings | **无**（Mojang 直接发布未映射的官方命名） |
| 主要代码标识符 | Yarn 类名、`MusicDiscItem`、`jukeboxPlayable` | Mojang 官方命名（`Component`、`Item.Properties`、`PackRepository`） |

### 3. 分发产物与清单存储 / Distribution Artifacts and Manifest Storage

**English**
The `dist/` directory stores precompiled `.jar` files for all 21 supported Minecraft versions, accompanied by `release-manifest.json` as the definitive metadata registry.

- **Why prebuilt jars in `dist/`?** Rebuilding 21 distinct Fabric Loom chains locally or in CI takes considerable time (4 to 13 minutes per version due to client jar remapping and dependency resolution). Committing the final <600 KB total binary payload ensures deterministic, immediate reproducibility and rapid CI synchronization.
- **`release-manifest.json`**: Acts as the single source of truth for the GitHub Actions publishing workflow, defining version slugs, target game loaders, dependency mappings, change logs, and cryptographic SHA1 hashes.

**中文**
`dist/` 目录存放着全部 21 个受支持 Minecraft 版本的预编译 `.jar` 文件，并配套 `release-manifest.json` 作为权威的元数据登记表。

- **为什么把预编译 jar 放进 `dist/`？** 在本地或 CI 中重新构建 21 条不同的 Fabric Loom 链耗时相当可观（每个版本因客户端 jar 重映射与依赖解析需要 4 到 13 分钟）。直接提交最终不足 600 KB 的二进制产物，可保证确定性、即时的可复现性，以及快速的 CI 同步。
- **`release-manifest.json`**：作为 GitHub Actions 发布流程的唯一事实来源，定义了版本 slug、目标游戏加载器、依赖映射、更新日志，以及密码学 **SHA1** 哈希值。

### 4. 自动化、工具与忽略项 / Automation, Tooling, and Ignores

**English**
The remaining top-level components manage CI synchronization and local workspace sanitation:

- **`.github/workflows/publish-modrinth.yml`**: Triggers on pushes modifying `dist/**` or `release-manifest.json`, invoking the synchronization script to mirror releases to Modrinth.
- **`tools/sync_modrinth.py`**: A Python-based idempotent synchronization script that checks local SHA1 hashes against remote Modrinth state, creating missing versions or replacing mismatched binaries.
- **`.gitignore`**: Excludes local Gradle build caches (`.gradle/`, `build/`, `build26/`), Python bytecodes (`__pycache__/`), heavy Mojang client jars (`tools/26.3-client.jar`, `loom-cache/`), and local environment secrets (`.env`, tokens).

**中文**
其余的顶层组件负责管理 CI 同步与本地工作区清理：
