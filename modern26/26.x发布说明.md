## 三、为什么这是一次完整移植

26.1 起 Mojang 停止混淆，整个 Fabric 开发链换了：

1. 插件 id 从 `fabric-loom` 换成 `net.fabricmc.fabric-loom`；
2. 删除 `mappings "net.fabricmc:yarn:..."`；
3. 依赖配置从 `modImplementation` 改为 `implementation`；
4. `remapJar` 改回普通 `jar`；
5. **11 个源码类的 `net.minecraft.*` 全部从 Yarn 名换成 Mojang 官方名**，主要对照：

| 旧（Yarn / 旧 Fabric API） | 新（Mojang 官方 / 26.x Fabric API） |
| --- | --- |
| `net.minecraft.text.Text` | `net.minecraft.network.chat.Component` |
| `net.minecraft.util.Identifier` | `net.minecraft.resources.Identifier` + `fromNamespaceAndPath` |
| `Item.Settings` / `maxCount(1)` | `Item.Properties` / `stacksTo(1)` |
| `net.minecraft.sound.SoundEvent` | `net.minecraft.sounds.SoundEvent` + `createVariableRangeEvent` |
| `Registries` / `RegistryKeys` | `BuiltInRegistries` / `Registries` / `ResourceKey.create` |
| `FabricItemGroup` | `FabricCreativeModeTab` |
| `displayName(...)` / `entries(...)` | `title(...)` / `displayItems(...)` |
| `ServerCommandSource` / `CommandManager` | `CommandSourceStack` / `Commands` |
| `ServerPlayerEntity` / `insertStack` | `ServerPlayer` / `Inventory.add` |
| `ResourcePackManager.scanPacks/enable` | `PackRepository.reload/setSelected` |
| `MinecraftClient.reloadResources` | `Minecraft.reloadResourcePacks` |

第一轮全量编译只报 1 个错（创造标签页 builder 的 `displayName`），改完即通过。

## 四、已知缺口与风险（发布前请务必看）

1. **只通过编译，没有进过游戏**。三个包只做了「依赖解析 + 编译 + 压缩包 CRC + class 数量 + 元数据声明」校验，
   其中 `26.3` 已由作者实机测试通过；`26.1` / `26.2` 仍**未在真实客户端启动验证**。建议补测，确认能进游戏、能开创造标签页、
   配置界面能打开、唱片能拿到手。
2. **唱片机播放链路仍有缺口**（与 1.21+ 那批相同）：物品侧用了 `jukeboxPlayable` 组件指向
   `JukeboxSong` 注册表键，但**没有生成 `data/minecraft/jukebox_song/*.json` 数据包**，
   而动态资源包目前只写 `assets` 下的 `sounds.json` 与 ogg。物品可能出现但**放上唱片机不响**。
   这是功能级缺口，需要单独补数据驱动链路并实机验证，不能靠编译通过掩盖。
3. `fabric.mod.json` 里 `environment` 仍是 `"client"`，但主入口注册了 `/customdiscs` 命令。
   专用服务器上本模组不会被加载；要支持服务端需改成 `"*"` 并重新构建、实机验证。
4. 资源包挂载是 best-effort：写入 `resourcepacks/CustomDiscs/` 后尝试自动启用，
   失败时会在日志提示玩家到「选项 → 资源包」手动启用。
5. **图标 / 封面**：图标已备（`icon.png` / `icon-256.png`，原创），MIT `LICENSE` 已备；封面横幅尚未准备。
6. **如实披露**：原 Custom Discs 项目版本不全或已停更；本 Neko Custom Discs 为重新自行设计、独立实现，未复制或改写该项目任何源代码与素材，无任何借鉴与抄袭。源码由 AI 辅助生成，平台询问时**如实披露**，不隐瞒、不改写规避。
7. 本版本使用 `1.20.0-alpha.19`（Loom alpha 分支），因为 26.x 目前只有这条免重映射链可用；
   后续 Loom 出稳定版时建议再回归一次。

## 五、上传步骤（M 站 / C 站）

本项目在 M 站已有 `Neko Custom Discs`（slug `nekocustomdiscs`，id `LjZ4jpPT`）的 18 个旧版本条目。
26.x 属于**追加 3 个新文件**，**不要删除已有的 18 个版本**。

- 解压 `CustomDiscs-1.0.0-26.x-3-versions.zip`，得到 3 个 jar；
- M 站项目页 → 版本 → 新建版本（或上传页一次多选 3 个文件）；
- **每个 jar 只勾对应的那一个游戏版本**（`26.1` / `26.2` / `26.3`），加载器选 `Fabric`，类型 `release`；
- 版本号建议沿用现有格式 `1.0.0-26.1` 等，名称沿用 `Neko Custom Discs 1.0.0-26.1`；
- 依赖按 `26.x上传清单.csv` 逐行挂：Fabric API、Cloth Config 必填，Mod Menu 可选；
- C 站同理，游戏版本按 jar 单独选，别勾范围。

自动化备选：`tools/upload_modrinth_26.py` 走 Modrinth 官方接口，**默认只预演、不删任何已有版本**，
令牌仅从环境变量 `MODRINTH_TOKEN` 或 `~/.modrinth_token` 读取，不写文件、不打印。需要时再说，未经确认不会执行。
